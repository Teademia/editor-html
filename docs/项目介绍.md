## 1. 项目总体介绍

- 本项目是一个面向视觉小说创作的综合工具链。
- 项目名称在代码中体现为 `The Ember Tavern`。
- 项目主体位于 `editor-html` 目录。
- 它不是单一播放器，而是包含以下功能：
  - 故事设定管理
  - 叙事结构规划
  - 节点式剧情编辑
  - AI 辅助生成剧情
  - AI 生成背景图
  - DTL 剧本导入导出
  - 网页端剧情预览
  - Godot 端正式运行

- 项目的核心目标是：
  - 帮助作者从故事设定开始创作视觉小说。
  - 将故事内容逐步转化为可运行的 Dialogic `.dtl` 剧情脚本。
  - 最终可以在网页播放器中预览，也可以导入 Godot 执行器中运行。

- 项目整体工作流如下：

```text
故事设定 / 世界观
    ↓
叙事节拍 / 功能块
    ↓
场景节点图
    ↓
AI 生成或人工编辑场景
    ↓
导出 Dialogic .dtl 剧本
    ↓
网页播放器预览 / Godot 执行器运行
```

## 3. 技术栈说明

### 3.1 前端技术栈

- Vue 3
  - 用于构建前端页面和交互逻辑。

- Vite
  - 用于前端开发服务器、构建和插件扩展。

- Vue Router
  - 用于实现首页、工作台、编辑器、播放器之间的页面切换。

- Drawflow
  - 用于实现可视化节点编辑器。
  - 一个剧情场景对应一个节点。
  - 节点之间的连线表示剧情跳转关系。

- localStorage
  - 用于保存当前工程、DTL 文本和播放进度。

- File System Access API
  - 用于选择本地 Godot 项目目录。
  - 用于将 DTL 和背景图写入 Godot 工程。

- AI 接口
  - 使用兼容 OpenAI 格式的聊天和图片生成接口。
  - 默认配置倾向 DeepSeek。

### 3.2 Godot 技术栈

- Godot 4.3
  - 作为最终视觉小说执行环境。

- Dialogic 插件
  - 用于运行 `.dtl` 剧情时间线。

- GDScript
  - 用于编写执行器逻辑、菜单系统、存档系统和 NPC 聊天系统。

## 6. DTL 剧本解析机制

- DTL 解析核心文件：

```text
src/utils/dtlEngine.js
```

- 该文件是项目的重要底层模块。

- 主要作用：
  - 将 DTL 文本解析为事件数组。
  - 将 DTL 文本转换为编辑器场景结构。
  - 将编辑器场景结构重新导出为 DTL 文本。
  - 在网页播放器中执行条件判断和变量变化。

### 6.1 parseDTL

- 函数作用：

```text
parseDTL(text)
```

- 负责逐行解析 DTL 文本。

- 可识别的语法包括：
  - `label`
  - `jump`
  - `set`
  - `if`
  - `elif`
  - `else`
  - `end`
  - `choice`
  - `background`
  - 普通旁白文本
  - 角色对话文本

- 返回结果包括：
  - `events`：事件数组。
  - `labelIndex`：场景名到事件位置的索引。
  - `startLabel`：默认起始场景。
  - `initSets`：剧情开始前的变量初始化语句。

### 6.2 evalCond

- 函数作用：

```text
evalCond(expr, state)
```

- 用于判断条件表达式是否成立。

- 示例：

```text
{经济} >= 3
{文化} < 2
```

- 实现过程：
  - 将 `{变量名}` 替换成当前变量值。
  - 再计算表达式结果。
  - 如果表达式异常，则返回 `false`。

### 6.3 applySet

- 函数作用：

```text
applySet(event, state)
```

- 用于执行变量赋值和变量变化。

- 支持的操作包括：

```text
=
+=
-=
*=
/=
```

- 示例：

```text
set {经济} += 1
set {科技} -= 1
set {政治} = 3
```

### 6.4 scenesFromDTL

- 函数作用：

```text
scenesFromDTL(text)
```

- 用于将 DTL 文本转换成编辑器使用的场景结构。

- 每个场景包含：
  - `name`：场景 label 名。
  - `lines`：正文内容。
  - `choices`：选项数组。
  - `end`：是否为结束场景。
  - `directJump`：无选项时的直接跳转目标。

### 6.5 dtlFromScenes

- 函数作用：

```text
dtlFromScenes(initSets, scenes)
```

- 用于将编辑器中的场景结构重新导出为 DTL 文本。

- 这是实现“可视化节点编辑”和“文本脚本导出”的关键。

## 7. 变量系统设计

- 变量系统文件：

```text
src/utils/variables.js
```

- 项目中固定了四个核心变量：

```text
经济
科技
文化
政治
```

- 变量工具函数：
  - `fixedVariables()`：返回固定变量列表。
  - `isCoreVariable(name)`：判断变量是否合法。
  - `coreVariableSets()`：生成变量初始化语句。

- 这样设计的原因：
  - 控制剧情分支复杂度。
  - 防止 AI 随意创造变量。
  - 保证 DTL 在播放器和 Godot 中都能稳定运行。

- 在以下环节都会检查变量是否合法：
  - DTL 解析。
  - 条件判断。
  - 变量赋值。
  - AI 生成内容。
  - DTL 导出。

## 9. AI 辅助创作实现

- AI 客户端文件：

```text
src/utils/aiClient.js
```

- 该模块使用兼容 OpenAI 的接口格式。

- 默认接口配置倾向 DeepSeek：

```text
https://api.deepseek.com/v1
```

- 支持的能力：
  - 检查 Story Bible。
  - 生成叙事骨架。
  - 推荐选择点。
  - 生成场景正文。
  - 生成图片提示词。
  - 生成背景图片。
  - 检查伏笔回收。

- AI 生成时的约束：
  - 必须使用中文创作。
  - 场景正文必须符合 DTL 格式。
  - 不允许输出 Markdown。
  - 不允许输出额外解释。
  - 不允许创造新变量。
  - 只能使用固定四个变量。
  - 如果不确定变量变化，就不写 `set`。

- 这样设计的优点：
  - AI 输出更稳定。
  - 剧情脚本更容易运行。
  - 减少格式错误。
  - 减少变量系统失控。

## 10. 节点图编辑实现

- 节点图依赖：

```text
drawflow
```

- 节点图的映射关系：

```text
一个节点 = 一个 DTL label 场景
一条连线 = 一个 jump 或选项跳转
节点内容 = 场景正文和跳转信息
```

- Studio 中相关函数包括：
  - `initGraph()`：初始化 Drawflow。
  - `loadBlockIntoGraph()`：加载当前功能块节点。
  - `addGraphSceneNode()`：添加场景节点。
  - `ensureSkeletonGraphNodes()`：根据骨架生成节点。
  - `refreshGraphNode()`：刷新节点显示。
  - `commitSceneEdit()`：保存当前节点正文。
  - `deleteSelectedNode()`：删除节点。
  - `playFromHere()`：从当前节点进入播放器。

- 节点图的作用：
  - 让剧情分支结构更直观。
  - 降低直接编辑 DTL 文本的难度。
  - 方便作者检查跳转关系。
  - 方便 AI 按节点逐段生成剧情。

## 15. 项目运行流程

### 15.1 创作流程

1. 用户进入 Studio。
2. 填写 Story Bible。
3. 选择叙事结构模板。
4. 系统生成节拍和功能块。
5. 用户编辑每个功能块的目标、冲突和选择点。
6. AI 生成叙事骨架。
7. 系统根据骨架生成场景节点。
8. AI 为每个节点生成 DTL 场景正文。
9. 用户在节点图中调整跳转关系。
10. 用户导出完整 DTL。

### 15.2 预览流程

1. Studio 生成或保存 DTL。
2. 播放器读取 `ember_dtl`。
3. 播放器解析 DTL。
4. 用户在网页中体验剧情分支。
5. 播放进度保存到 `ember_progress`。

### 15.3 Godot 运行流程

1. 用户选择 Godot 项目目录。
2. Studio 将 DTL 写入 `executor/timelines/`。
3. Studio 将背景图写入 `executor/assets/backgrounds/`。
4. Godot 执行器读取 DTL。
5. Dialogic 运行剧情。
6. Godot 执行器提供菜单、存档、日程、科技树等完整游戏系统。

## 16. 项目特点

## 17. 当前代码中需要注意的问题

  - 可能是文件编码和终端解码方式不一致。
  - 如果浏览器和 Godot 中显示正常，则主要是终端问题。
  - 如果运行界面也乱码，则需要统一源码编码为 UTF-8。

- `StudioView.vue` 文件较大。
  - 该文件集中了工程管理、AI、节点图、图片生成和 Godot 写入等功能。
  - 后期维护时可以考虑拆分模块。

- 可拆分方向：
  - `projectStore`：工程状态管理。
  - `graphEditor`：节点图管理。
  - `aiWorkflow`：AI 生成流程。
  - `dtlExporter`：DTL 导入导出。
  - `godotBridge`：Godot 工程写入。
  - `imageGenerator`：图片生成与保存。

## 18. 总结

- 本项目是一个围绕视觉小说创作流程设计的综合系统。

- 它的核心实现思路是：
  - 使用 Vue 构建网页创作工具。
  - 使用 Drawflow 实现节点化剧情编辑。
  - 使用自定义 DTL 解析器实现文本和结构之间的转换。
  - 使用 AI 辅助生成故事骨架、场景正文和背景图。
  - 使用 localStorage 和 `.vnproject` 保存工程。
  - 使用网页播放器进行快速预览。
  - 使用 Godot + Dialogic 执行最终视觉小说。

- 项目的重点不只是“生成文本”，而是将以下能力连接起来：
  - AI 创作
  - 结构化剧情设计
  - 节点图编辑
  - 变量控制
  - 网页预览
  - Godot 游戏执行

- 因此，该项目可以看作一个面向视觉小说创作者的完整创作与执行平台。
